# 独立股票前端重建

2026-10-26：旧项目已被用户删除，本项目按用户确认范围重新开发，首版只做信号筛选和观察池。

此前 `personal-homepage` 曾实现股票功能，并在提交 `0da7a7e` 中移除。这里重新编写应用外壳、页面、组件、状态管理与请求层；不恢复历史页面模板。项目复用现有 Vue 工具链版本与后端协议。主站及管理后台此次不修改。

## 服务端契约

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| GET /stock-signals/dates | 已完成扫描日期与命中数 | 公开 |
| GET /stock-signals/sectors?codes=000030,600519 | 当前行业层级与主题概念，每批最多 50 只 | 公开 |
| GET /stock-signals/performance?date=YYYY-MM-DD&codes=600396,000030 | 筛选当日和该日收盘至今的涨幅，每批最多 50 只 | 公开 |
| GET /stock-signals?date=YYYY-MM-DD | 日期缓存；404 表示尚未扫描 | 公开 |
| POST /stock-signals/scans | 不带 codes 为全市场异步任务，带 codes 为同步结果 | JWT |
| GET /stock-signals/scans/:id | 任务进度，done 时附结果 | 公开 |
| GET /stock-watchlist | 当前用户清单 | JWT |
| POST /stock-watchlist | 批量入池，返回 added / invalid / duplicated / overflow | JWT |
| POST /stock-watchlist/check | 手动检查并返回完整清单 | JWT |
| DELETE /stock-watchlist/:id | 删除本人条目 | JWT |

前缀为 `/api`。指定代码单次最多 500 个；批量入池单次最多 100 个，个人观察池总容量 100 只。B 对应信号值 1；S 由服务端检查入池依据日期之后的信号值 0 并锁定状态。

观察池检查补查新浪返回的历史事件，而非只刷新当天：每只待观察股票请求一次历史，补齐 `入池依据日 < S 日期 <= 今天` 的真实 S 后评估；已触发条目保持锁定。定时补查先于当日扫描，避免被当日无事件或扫描失败跳过。

`POST /stock-watchlist/check` 返回 `{ checked, triggered, failed, items }`，其中 `checked` 是成功读取历史的待观察代码数，`triggered` 是实际新增数，`failed` 是读取失败代码。`新增 0` 不能理解为池内没有 S；全部已触发时可以 `checked=0`。入池响应额外返回 `checkFailed`，表示入池成功但历史补查未完成。前端兼容旧响应缺少这两个失败字段，但应先发新版后端以使历史范围提示准确。

历史 S 取符合区间的最大日期，排除入池依据日当天与未来日期。只恢复源站当前返回和数据库已保存的事件，不保证恢复源站缺失的更早历史。实现与只读诊断见后端 `docs/plans/2026-10-26-watchlist-history-impl.md`。

## 并发与身份

每次查询/扫描生成新的代际与 AbortController，迟到结果不得覆盖新选择。页面卸载取消客户端等待，服务端任务继续运行；运行任务 ID 保留在 URL，刷新后可恢复查询。任务结束清除 URL 中的 run 参数。

个人观察池是一份共享状态，账号切换先清空；查询与写操作以会话代际核对身份，迟到响应不写回新账号。401 刷新采用共享 Promise，刷新期间退出后不得恢复旧令牌。

## 行业与概念板块（2026-10-26）

结果表展示股票、行业板块、概念板块和观察状态，去掉市场、信号日期与固定 B 信号值三列；查询日期及信号含义仍由页面筛选条件与统计说明。股票原有 `market` 字段继续用于后端入池操作。

板块独立请求 `GET /stock-signals/sectors`，响应 `items` 每项包含 `code`、`industries: { code, name, level }[]`、`concepts: { code, name }[]`、`status: ready | unavailable`、`source: eastmoney`、`fetchedAt: string | null`。只读公开接口，不依赖用户身份，不写入观察池或信号缓存。

前端每批 25 只，最多两个并发请求；板块查询不阻塞股票结果、复制与勾选。切换日期、重试或卸载时取消旧请求，迟到结果不回填。概念默认显示三个，展开可查看全部；手机端使用卡片布局。

行业与概念来自东方财富当前归属，不是所选信号日期的历史快照。行业按 1–3 级排列；概念仅展示数据源明确标记的主题，排除地域、指数成分和交易属性。成功响应无主题概念显示“暂无主题概念”；未取到数据或接口失败显示“暂不可用”，可重试。后端成功缓存 6 小时、失败缓存 60 秒，因此来源失败后需稍后重试。

后端实现在独立工作目录 `../tuanzi-server-stock-sectors`，分支 `feature/stock-sector-metadata`；原 `../tuanzi-server-base` 的其他未提交改动未修改。先发布该后端接口，再发布前端；旧后端没有此接口时，前端会降级显示板块不可用。无新依赖、环境变量或数据库迁移。本任务尚未部署。

## 筛选日涨幅与距今涨幅（2026-10-27）

筛选表增加“当日涨幅”和“距今涨幅”。当日指所选筛选日期：历史日直接读取东方财富该日的涨跌幅字段；距今按最新报价相对筛选日前复权收盘价计算。不是按点击查询时的今天，也不是按实际加入观察池的日期。

独立公开接口 `GET /stock-signals/performance` 接收 `date` 和逗号分隔的 `codes`。返回 `items`，包含 `code`、`date`、`dayPercent`、`sincePercent`、`dayReason`、`sinceReason`、`quoteAsOf`、`source=eastmoney`、`adjustment=qfq` 和 `fetchedAt`。百分比直接以 12.34 表示 12.34%，缺失为 null，真实零为 0。

今天盘中筛选时，当日涨幅采用当前报价的当日涨跌幅，距今显示“待收盘”；到上海 15:00 且行情报价也已到当天收盘后才计算累计。所选日无行情不借用邻近交易日，没有基准或有效最新报价不填零。报价时间标在距今涨幅下方，停牌/非交易日保留原实际报价时间。

前端十只一批、最多两个并发任务，股票列表和勾选不等待行情；页面可见时每轮完成后 30 秒刷新，隐藏时跳过刷新。日期切换、重试和卸载均取消旧请求与定时器。后端全局四路并发、成功/部分有效缓存 30 秒、全缺失缓存 5 秒。

当日历史涨幅使用东方财富日线 `f59`，当前日使用实时报价 `f170`；距今涨幅仍以筛选日前复权收盘为基准。后端读取筛选日期前 45 天起、最多 1200 条前复权日线，缺少目标或有效最新报价时明确缺失。报价和历史数据都来自东方财富，不自动回退到腾讯；一类数据失败不阻断另一类已取得的数据。实现记录见 `../tuanzi-server-stock-sectors/docs/plans/2026-10-27-signal-price-returns-impl.md`。前后端当前分支为 `feature/unify-market-source`，包含前序涨幅功能。统一数据源记录见后端 `docs/plans/2026-10-27-unify-market-source-impl.md`。无配置、依赖和数据库迁移；先发布后端，再发布前端，本次尚未部署。
